Detailed Description

The files from which PlaybackResourcesFactory::create builds dom::PlaybackResources.

The factory does not search for files. These may be found in the standard locations in a Finale installation, where [version] is the Finale version, such as 27:

File type macOS Windows
Soundmaps (*.soundmap, such as GIFF.soundmap and SoftSynth.soundmap) /Library/Application Support/MakeMusic/Finale [version]/Data/ C:\Program Files\MakeMusic\Finale\[version]\Data\\endiskip
MIDI Device Annotation files (*.xml, such as Garritan Instruments for Finale.xml) /Library/Application Support/MakeMusic/Finale [version]/MIDI Device Annotation/ C:\ProgramData\MakeMusic\Finale [version]\MIDI Device Annotation\\endiskip
Per-user MIDI Device Annotation files ~/Library/Application Support/MakeMusic/Finale [version]/MIDI Device Annotation/ C:\Users\[user name]\AppData\Roaming\MakeMusic\Finale [version]\MIDI Device Annotation\\endiskip

The per-user folder holds copies of the shared files and may also hold files that the user or third-party playback software installed. Third-party playback software may install its soundmap elsewhere, such as /Applications/Garritan Instruments for Finale/GIFF.soundmap on macOS. Some older versions keep General MIDI.soundmap and SoftSynth.soundmap inside the application bundle, in Finale.app/Contents/Resources/ on macOS.

std::vector<PlaybackResourceFile> musx::factory::PlaybackResourceInputs::instrumentCatalogs

Instrument catalog XML files (root <InstrumentCatalog>), in priority order. Their names are used only in error messages.

Finale does not ship a file in this form. It is an XML export of the instruments in one of Finale's SQLite instrument databases, which a standard Finale 27 installation keeps in these locations. On macOS they are inside the application bundle; earlier versions name the bundle Finale [version].app.

Database macOS Windows
Instruments used when converting older documents (2012FileConverter.instruments) /Applications/Finale.app/Contents/PlugIns/2012FileConverter.bundle/Contents/Resources/ C:\Program Files\MakeMusic\Finale\27\2012Converter\Resources\\endiskip
Instruments of the current version (Finale.instruments) /Applications/Finale.app/Contents/Resources/ C:\Program Files\MakeMusic\Finale\27\Resources\\endiskip

Each file has this layout:

<?xml version="1.0" encoding="utf-8"?>
<InstrumentCatalog>
<Instrument uuid="616b3bf9-58df-4b44-8339-9f66461ac910" name="Horn in F" fullName="Horn in F"
clef="treble" notation="standard" transposition="-7"/>
<!-- one <Instrument> per instrument -->
</InstrumentCatalog>
Attribute Required value
uuid The instrument's UUID, the same value a soundmap's <MapSounds><FinInstrument uuid> names. dom::PlaybackResources::findMappedSound matches it case-insensitively.
name The instrument's internal name.
fullName The instrument's full staff name.
clef The clef name of the instrument's first staff, such as treble, bass, alto, treble8vb, altpercussion, tab1, or blank.
notation The notation style name, such as standard, percussion, tab, or colornotes.
transposition A signed decimal integer: sounding pitch minus written pitch, in semitones. For example, -7 for Horn in F and 0 for a nontransposing instrument.

Every attribute is required and must be non-empty after trimming; a missing attribute or a transposition that is not an integer throws. Other attributes and other child elements of the root are ignored. Entries are retained in file order; see dom::PlaybackResources::getInstruments.
